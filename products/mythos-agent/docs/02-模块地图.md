# 模块地图

本页定义 Mythos Agent 产品层的职责分区。DeepSeek Harness 通用包的完整清单以 [`packages/README.md`](../../../packages/README.md) 为真源，本页不复制上游目录。

## 产品模块

| 模块 | 责任 | 当前完成边界 | 明确缺口 |
|---|---|---|---|
| Product launch | 为 Interactive CLI、Headless 和 Web 构造稳定启动环境 | 源码/发布路径分离、固定 `DSH_HOME`、HTTPS 网关、信号转发、交互式 resume、Web loopback | CLI 渠道安装与跨版本会话升级策略尚未定义 |
| Product config | 防止 Headless/Web 身份和能力漂移 | 验证 Bundle、单模型、persona、网关、Preset 和 UI 禁用项 | 模型身份变更的正式迁移和回滚策略尚未形成 |
| Agent preset | 组合 Mythos 工具、状态与行为能力 | 文件、Shell、Web、skill、goal、plan、todo、compaction、job、subagent 和 workflow 已装配 | 不同产品档位或任务类型的实证组合尚未建立 |
| Evaluation | 在可重现环境中评估任务完成 | 10 个单轮用例、1 个普通旅程、2 个高级旅程和 2 个真实仓库用例 | 更多真实语言、仓库规模、权限模式和长时间任务覆盖 |
| Evidence contract | 绑定配置、执行快照、真实运行身份、计费、原始会话和外部验收 | 内容寻址归档、离线快照重验、runtime observer、来源校验、字节级证据和严格入口解析 | 需要对长期数据保留、迁移和损坏恢复建立运维演练 |
| Flywheel | 归档会话、导入服务端数据、生成 cohort 分析与筛选集 | 原始会话归档、分析、server dataset、curation 和多类门禁已实现 | 筛选数据如何转化为可对照的 harness 改进实验尚未闭环 |
| Release | 产生与消费自包含、确定、可验完整性的产品包 | 冻结 lockfile 闭包、Web 构建、符号链接收口、完整性清单、双 staging 字节级确定性、Headless/Web/M3/篡改消费端验证 | CLI 安装渠道、发布签名与跨版本回滚尚未建立 |
| Desktop | 为 macOS 用户托管 Mythos Web 运行时与更新 | Electron 壳、内置运行时、受管服务路由、签名热配置、应用更新状态、DMG/ZIP 产物 | Developer ID/Notarization 闭环、远程渠道发布、升级与回滚实机演练尚未完成 |
| Controller | 代表用户作战略决策与阶段复审 | 宪法策略、串行决策、乐观并发控制、原子文件记忆、watchdog 已有代码和测试 | 尚未与真实 Lead、项目状态源和产品运行时装配 |

## 用户任务能力地图

| 能力 | 主要机制 | 当前评测证据 |
|---|---|---|
| 精确文件交付 | 文件工具 + 外部字节校验 | `exact-file` |
| 受保护测试的缺陷修复 | Shell + 范围约束 + 修改后验证 | `bugfix-protected-test` |
| 凭据隔离 | Shell 环境过滤 + 发布密钥扫描 | `credential-isolation` |
| 跨文件约定修复 | 仓库搜索 + 多文件编辑 + 受保护 verifier | `multi-file-contract` |
| 只读诊断 | 任务意图识别 + 文件系统只读行为 | `diagnosis-only` |
| 并发去重 | 多模块推理 + 隐藏验证 | `async-deduplication` |
| 路径安全 | 工作区策略 + 边界验收 | `security-path-boundary` |
| 大工作区定位 | 搜索、采样与范围控制 | `large-workspace-targeting` |
| 工具失败恢复 | 失败结果可见性 + 替代执行路径 | `failure-recovery` |
| 无操作判断 | 证据驱动的不修改决策 | `no-op-evidence` |
| 冷恢复多轮实现 | 持久会话 + 恢复边界 + 分阶段证据 | `journey-cold-resume-feature` |
| 压缩后任务连续 | 上下文压缩 + 会话记忆 + 隐藏验证 | `journey-compaction-continuity` |
| 并行 subagent 集成 | 并行委派 + 父 agent 整合 + 外部验收 | `journey-subagent-parallel` |
| 真实仓库范围修复 | 固定仓库修订 + 未来测试 + 目标路径守卫 | `dsh-session-seed-identity`, `dsh-pwsh-prompt-collision` |

## 模块依赖原则

1. Product 可以组合 Harness，不得在产品目录内 fork 通用 agent loop、Session 或工具实现。
2. Evaluation 可以调用产品真实入口，不得绕过产品配置直接伪造通过样本。
3. Flywheel 只派生数据与质量决策，不覆盖原始会话、原始计费或评测证据。
4. Release 消费已验收的代码、配置和 cohort，不在打包阶段修复产品。
5. Desktop 只托管一份已验证运行闭包和产品展示，不修改 DSH 运行时或将受管基础设施暴露给用户。
6. Controller 只通过审计端口输出决策，不得获得任何执行工具。
