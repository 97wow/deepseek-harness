# 愿景与原则

## 使命

Mythos Agent 是基于 DeepSeek Harness 的用户侧 coding agent（编程智能体）产品。它的目标是在真实、多轮、复杂软件工程任务中稳定完成用户目标，并将每次执行的原始会话、工具轨迹、验收证据和计费数据累积为可追溯的质量飞轮。

Mythos Agent 不是 MythosV3 中转站、单一提示词模板、评测数据集或 MYTHOS 总控。MythosV3 提供服务端能力，M3 是项目模型目标，总控负责战略决策，Mythos Agent 则是最终与用户协作的产品。

## 成功定义

1. 对真实代码库的修复、实现、诊断、评审和长任务具有稳定的端到端完成能力。
2. 完成声明由外部可重现的测试、评测、运行或发布证据支撑，不使用模型自评代替验收。
3. 长会话在压缩、冷恢复、失败重试和 subagent 协作后仍保持目标、范围和证据连续性。
4. 评测、生产会话与 API 使用数据保留原始真源，派生标注可重建且不覆盖原始数据。
5. 改进优先落在 harness、状态机、工具、记忆、上下文工程、验证和控制机制，提示词只承载必要的稳定行为。

## 不可违背原则

1. **Harness 优先**：能用可测的机制、类型、状态或门禁解决的问题，不使用额外提示词堆叠规则。
2. **证据先于声明**：完成、改进和发布必须绑定可复查证据；缺少证据时状态只能是未验收。
3. **M3 主线优先**：未完成 M3 与完整 DSH 工作流基线前，Qwen 等本地模型只作为参考组，不替代主线判断。
4. **原始数据优先**：采集层最大化保留原始内容、身份、使用量和执行证据；发布包与日志输出仍必须严格隔离凭据。
5. **权限不扩张**：诊断、评审和状态任务保持只读；实现任务只做完成目标所需的最小更改；不可逆或需要新授权的决策升级给用户。
6. **总控不执行**：MYTHOS 总控只决策、授权、否决、暂停和验收；Lead 与 Worker 负责执行。
7. **整体最优**：局部通过率、速度或 token 成本的改进，不得以损害任务完成率、可维护性、安全边界或数据飞轮为代价。

## 明确不做

- 不把产品退化成只能处理固定 demo 的提示词包装。
- 不用单次成功、手工筛选 transcript 或无原始数据的汇总指标作为发布证据。
- 不在没有可复现瓶颈前引入多个模型路由、复杂编排平台或大量可调参数。
- 不把运行会话、凭据、本地设置、评测原始数据或飞轮数据打入发布包。
