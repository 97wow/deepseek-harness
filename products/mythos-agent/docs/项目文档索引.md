# Mythos Agent 项目文档

本目录是 Mythos Agent 的项目管理入口，补充 DeepSeek Harness 仓库已有的架构、子系统和贡献者文档。它只管理 Mythos Agent 产品的愿景、边界、路线图、进度、开发规则与质量证据，不复制通用 DSH 技术参考。

## 文档导航

- [`00-愿景与原则.md`](00-愿景与原则.md)：产品使命、成功定义、不可违背原则与明确非目标。
- [`01-产品架构.md`](01-产品架构.md)：产品与 DSH、模型网关、评测、飞轮、发布和总控的边界。
- [`02-模块地图.md`](02-模块地图.md)：产品目录职责、能力覆盖、当前完成边界和已知缺口。
- [`03-路线图.md`](03-路线图.md)：从产品基线、评测飞轮到总控与运维闭环的里程碑和退出标准。
- [`04-进度看板.md`](04-进度看板.md)：唯一的人工项目进度真源，记录工作项状态、核验事实和下一执行顺序。
- [`05-开发规则.md`](05-开发规则.md)：代码归属、配置、评测、数据、安全、验证与 Git 约束。
- [`06-评测与发布.md`](06-评测与发布.md)：评测分层、cohort 身份、发布门禁、打包约定和完成定义。

进度看板可以解释当前阶段，但不重写生成评测数据。数字与代码、配置或生成产物不一致时，先以可执行真源复核，再修正看板。

## 维护规则

1. 产品范围、原则或非目标变化时，更新 `00-愿景与原则.md` 与对应 Agent Note。
2. 产品目录、数据流、DSH 组合边界或 Desktop 托管关系变化时，更新 `01-产品架构.md` 和 `02-模块地图.md`。
3. 新功能先归入路线图里程碑，再创建进度工作项；不直接把一个想法标记为当前任务。
4. 进度项只有在验收证据存在时标记为完成；阻塞项写明原因和解除条件。
5. 评测、发布和安全规则变化时，同步更新 `05-开发规则.md`、`06-评测与发布.md` 与相关自动化测试。
